### Dhan MCP — root cause found and fixed (this is a KB amendment)

The MCP `login` → `complete_login` consent flow failed **4 times across 02 and 03-Sep**, always with
`token_id already consumed for this session` followed by `API Error: Unauthorized` on every agent tool.
It was previously logged as a Dhan-side regression. **That diagnosis was wrong.**

The actual cause was a **stale OAuth client registration on this machine**. Fix:

```
claude mcp remove dhan -s local
claude mcp add --transport http --client-id "$DHAN_CLIENT_ID" dhan https://mcp.dhan.co/mcp
/mcp → open dhan → Authenticate
```

`claude mcp get dhan` then reads `OAuth: client_id configured`. **No `mcp__dhan__login` call was needed
afterwards** — data flowed immediately. Three sessions were spent on the wrong layer.

**Diagnose by error string:**

| Error | Layer | Action |
|---|---|---|
| `API Error: Unauthorized` | reached Dhan, rejected there | stale client registration → do the reset |
| `requires re-authorization (token expired)` | blocked locally by Claude Code OAuth | `/mcp` → Authenticate |

⚠️ `claude mcp list` showing **✔ Connected** and `/mcp` showing `dhan · connected · 11 tools` are both
**transport-level only** and were green throughout all four failures. Only `expirylist` is proof.
